# 边界规则与验收说明

## 时间语义

周期规则不保存“当天截止时间”，而是保存：

- `weekday`：周一为 0，周日为 6；
- `start_minute`：门店当地挂钟起点；
- `duration_minutes`：持续时长；
- `disambiguation`：DST 重复时的策略。

因此 `周五 22:00–02:00` 是一个从周五当地时间开始、延伸到周六凌晨的实际实例。状态判断用 UTC 点时间与实例相交，不用浏览器当天日期做截断。

## DST

### 秋季重复

America/New_York 在 `2026-11-01 01:00` 回拨：

- 第一次 01:00：`2026-11-01T05:00:00Z`（EDT, UTC-4）；
- 第二次 01:00：`2026-11-01T06:00:00Z`（EST, UTC-5）。

周期生成器对重复挂钟产生两个窗口。活动创建时可用 `disambiguation: "first" | "second"` 明确绑定其中一个实际场次；`compatible` 选择第一个，但周期窗口仍保留两个实际营业实例。

### 春季跳字

`2027-03-14 02:30` 在 America/New_York 不存在。默认策略是顺延到 `03:00 EDT`，即 `07:30Z`。若活动挂钟为 `02:30–03:30`，结束时间由“实际起点 + 60 分钟”得到 `08:30Z`，避免把起点和终点分别独立换算成同一时刻。

## 有效营业窗口

```text
有效营业 = UNION(常规营业, 临时加开) - 临时闭店
```

- 临时闭店可与常规时段重叠，也可覆盖整天；
- 临时加开不能抵消临时闭店；
- 输出窗口保留来源 ID；
- 相邻或重叠的有效窗口会合并；
- 闭店挖空后可能产生前后两段。

## 闭店专场

`event_sessions.closed_required` 在创建或营业边界变化时由闭店 digest 计算：

1. 活动完全被有效营业窗口覆盖：无需授权；
2. 任一部分落在闭店区间：需要显式授权；
3. 未授权：公开列表隐藏该活动（管理端可查），报名返回错误，不能自动取消或自动放行；
4. 管理员调用授权接口后 `authorized=1`，记录说明、操作者和时间；
5. 周期时间、例外或店铺合并改变闭店 digest：旧授权清空，必须重新授权。

## 查询版与缓存

1. 客户端 `POST /apiqueries` 创建 `query_versions`。
2. 地图和列表必须传同一个 queryId。
3. 更名、合并等手工更正递增 catalog version。
4. 旧 queryId 调地图或列表返回 409，前端重建查询版。
5. 门店小时修改递增该店 `hours_version`，删除该店状态缓存。
6. `status_cache.next_change_ms` 即缓存到期点；到点后重算。
7. 预生成窗口和实时窗口对账。若不一致，服务端重建并再次校验；结果包含 `window_consistent`。

## 预约并发与回执

报名在 SQLite 事务中完成：

- 检查活动未结束、未取消；
- 闭店私场必须已授权；
- `booked_count + seats <= capacity`；
- 条件更新余量；
- 触发器兜底拒绝超卖。

回执快照保存实际 UTC session，而不是只保存挂钟时间。之后即使门店合并、更名或活动迁移，回执仍能证明报名时绑定的场次，同时可显示当前承接门店名称。

## 自动化验收

`npm test` 覆盖：

1. 秋季 DST 重复时段；
2. 春季 DST 跳字顺延；
3. 跨午夜归属与临时闭店优先；
4. 闭店活动未授权拒绝、授权后可报名；
5. 新增闭店导致旧授权失效；
6. 缓存到期点、手工更正、同 queryId 地图/列表与 409 传播；
7. SQLite 多连接最后席位并发抢占；
8. 店铺合并更名后的历史名、活动转移与回执快照；
9. 预生成窗口对账、临时加开与历史 as-of 不冒充当前。
